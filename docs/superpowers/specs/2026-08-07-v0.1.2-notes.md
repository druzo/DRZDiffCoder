## Executive Summary

**DRZ Diff v0.1.2** hardens the cross-platform release pipeline that shipped in v0.1.0. The release ships every artifact under CI control via GitHub Actions, adds an **RPM** package family alongside the existing `.deb`, and publishes a reproducible Linux build image to `ghcr.io` for future self-hosted runners.

The application surface is unchanged from v0.1.1 (no behavioural diff). v0.1.2 is a **toolchain release**: the same binaries you ran in v0.1.0 are now produced by a CI pipeline that monitors itself, fixes itself, and validates every asset before publishing.

**Why it matters:** teams that standardize on RPM-based distros (Fedora, RHEL, openSUSE, Amazon Linux) can now `dnf install drzdiff` without leaving their package manager. The release process is no longer dependent on a single maintainer's local environment.

## New Features

### Release pipeline (`scripts/release/`, `tools/`, `docker/`, `.github/workflows/`)

- **`build-rpm.sh`** — produces `.rpm` for `x86_64` and `aarch64` via `rpmbuild` + `drz-app.spec` (RPM 4.19+).
- **`drz-app.spec`** — single template; `%{_arch}` and `%{version}` interpolated by `rpmbuild`.
- **`docker/linux-builder.Dockerfile`** — Ubuntu 24.04 image with: rustup stable, `gcc-mingw-w64-x86-64`, `gcc-aarch64-linux-gnu`, `dpkg-dev`, `fakeroot`, `rpm-build`, `appimagetool` (legacy AppImageKit 13), ImageMagick, `wixl`, `libdmg-hfsplus` build prereqs.
- **`docker/release.Dockerfile`** — slim runtime wrapping the build output (used by self-hosted runners).
- **`docker/entrypoint.sh`** — wraps `scripts/release.sh` with the right `VERSION` env.
- **`.github/workflows/ci.yml`** — `fmt --check` → `clippy --workspace --all-targets -- -D warnings` → `cargo test --workspace`. Triggers on push to `main`/`develop` and on PRs targeting them.
- **`.github/workflows/release.yml`** — tag `v*.*.*` push → 6-job matrix (linux-x86_64, linux-arm64, windows-x86_64, macos-x86_64, macos-arm64, release) → uploads all artifacts + `SHA256SUMS.txt` via `softprops/action-gh-release@v2`.
- **`.github/workflows/docker.yml`** — builds and pushes `ghcr.io/druzo/drzdiff-linux-builder` on `main` push + manual `workflow_dispatch`.
- **`tools/release-doctor.sh`** — pre-flight: validates workflow files, scripts, Dockerfiles, `Cargo.toml` versions align.
- **`tools/monitor-workflow.sh`** — polls `gh run view` until all jobs finish; on failure, fetches log, prints diagnosis hints.
- **`tools/collect-artifacts.sh`** — assembles + sha256-sums every artifact across the release folder.

### Package addition

- **`scripts/release/install-prereqs.sh`** — added `rpm` (Debian package: `rpm`) to the APT list. Idempotent.

## Known Limitations

- **Binaries are unsigned.** Windows SmartScreen warning on first run; macOS Gatekeeper warning on first run; RPM/DEB unsigned. Matches v0.1.0.
- **No universal macOS binary.** `.app` per arch; user picks the right `.dmg`. (Roadmap.)
- **No code signing infrastructure.** Roadmap item — out of scope for v0.1.2.
- **`.rpm` builds require `rpmbuild` ≥ 4.19** (matches Fedora 33+, RHEL 9+, openSUSE Leap 15.4+). Older distros will need manual `rpm --force` or rebuild from the spec.
- **CI `.dmg` generation on macOS runners** uses `libdmg-hfsplus` (built on the fly) rather than `hdiutil` for cross-arch consistency. The output is functionally equivalent.
